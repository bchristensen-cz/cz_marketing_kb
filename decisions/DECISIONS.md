# Decision ledger

One place for every decision that more than one project, tab, mart or skill depends on. The skills and dictionaries say *how* a thing is defined; this file says *what was decided, when, by whom, and where it is applied*, so a session in any Claude project (Dashboards, Data Documentation, Analysis) can find the ruling without reading another project's memory.

## How to use this file

- **Read it at session start**, after `README.md` and before any domain skill. Every project's instructions point here.
- **Append at session close.** Any decision made this session that another project could depend on (a metric definition, an attribution rule, a filter default, a table of record, a naming rule, a lifecycle rule) gets a row. Commit and push with the rest of the KB update.
- **One row per decision.** Supersede, never edit history: add a new row and set the old one's status to `superseded by D-NNN`.
- **Link, don't copy.** The row carries the ruling in one or two sentences and points at the file that holds the reasoning (a skill section, a design doc, a repo doc). Numbers and revenue figures stay in the source docs, not here; this repo is public.
- **Projects:** `KB` = the Data Documentation project (steward, marts, skills, dictionaries); `Dashboards` = the company dashboard (repo `cz-dashboard`, private); `Analysis` = the shared company question-answering project. A decision made in one project and applied in another lists both.

Row format: ID | Date | Made in | Decision | Applied in | Source | Status.

### Resolved

- **Attribution window, 72h (D-007) vs 24h / Saturday 48h (D-022).** Resolved 2026-09-24 by D-026: 24h / Saturday 48h is the company definition on every surface. The July design measured a flat curve past day 3 and chose 72h; the September dashboard measurement found the order rate falls off at 24 hours with a Saturday-to-Monday bump, and that rule is live. The `cam_agg_*` build follows D-026.

## Adding a row

Copy the last row, take the next ID, fill the date the decision was made (not the date you wrote it down), name the project it was made in, keep the decision to what a reader needs to apply it, and link the file that holds the reasoning. If the decision replaces an earlier one, set the earlier row's status to `superseded by D-NNN` in the same commit.
